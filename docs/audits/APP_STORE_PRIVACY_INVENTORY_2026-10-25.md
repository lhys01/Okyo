# Okyo App Privacy inventory — October 25, 2026

Status: source-derived answers prepared; final owner/privacy review and the actual enabled Production vendor configuration remain required. Do not attest that no data is collected. Do not submit these answers until the final build and vendor dashboards are reconciled.

Apple requires collection by integrated partners as well as Okyo. Purely on-device processing is excluded. A persistent anonymous identifier is not sufficient to call data unlinked when it identifies an installation/device. Food uploads are conservatively included because external AI-provider retention has not been verified, even though Okyo's runtime database excludes image bytes. These are engineering classifications, not a legal determination.

## Retention, deletion and review boundaries

The app stores user state locally. The API stores scoped temporary analysis (15 minutes), recipe working records (24 hours), and short-lived caches; expiry prevents serving expired records, and physical cleanup/backup retention is separate. The runtime database strips image bytes and credential fields. Account deletion verifies the session, requests vendor deletion and clears the scoped API state, then the app performs local-image/state/reminder/identity cleanup and returns to the first onboarding screen. Vendor operational, backup and statutory purchase retention require agreement/dashboard review; no immediate universal deletion claim is made. Deletion was exercised only with injected test doubles; no account was deleted during this audit.
