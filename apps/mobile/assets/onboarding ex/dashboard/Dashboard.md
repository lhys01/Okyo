HOME DASHBOARD

Structural Reference

Use the Cal AI reference graph3.webp as the structural source of truth for the Home dashboard.

The goal is to closely follow its overall hierarchy and dashboard organization while translating it into Okyo's own visual identity.

graph3.webp is a STRUCTURAL reference, not the Okyo brand itself.

Core Rule

The dashboard is the SAME for every user.

Do NOT create separate Home dashboards for:

Save Money

Eat Healthier

Hit My Macros

All users get the same dashboard structure, components, navigation, colors, and visual system.

The user's onboarding goal only changes which metric section appears FIRST in the swipeable metric carousel.

Save Money user

Savings → Macros → Health

Hit My Macros user

Macros → Savings → Health

Eat Healthier user

Health → Savings → Macros

All three sections are always available to every user.

Goal personalization changes PRIORITY, not the app's visual identity.

HOME STRUCTURE

1. Header

At the top:

Okyo greeting

user name where appropriate

small supporting Okyo/Kiko presence only if it improves the composition

Example:

Good morning, Megan

Keep the header compact.

Do not waste large amounts of vertical space.

2. Week Calendar

Directly below the header, use a compact week calendar modeled closely on the structure of graph3.webp.

Show the current week.

The calendar should eventually be able to reflect meaningful Okyo activity, such as days where the user made or saved a meal.

Do not include the calendar only as decoration.

Keep it visually lightweight and integrated with the dashboard.

3. Swipeable Metric Carousel

This is the main dashboard section.

Create a horizontal swipeable carousel with exactly three primary categories:

Savings

Macros

Health

The selected onboarding goal determines which category is shown first.

Users can swipe horizontally between all three.

Do NOT hide the other categories.

Do NOT create three different dashboard designs.

Do NOT change the entire screen background based on the selected category.

The carousel should feel like one consistent Okyo component with different data emphasis.

SAVINGS SECTION

Primary Metric

Estimated savings this month

Example visual value:

$84 saved this month

IMPORTANT:

$84 is an example design value only.

The live dashboard must calculate savings from the user's actual Okyo activity.

Never hardcode $84 as a real user result.

Never claim guaranteed savings.

Use estimated values and clearly defined assumptions where needed.

Supporting Metrics

Possible supporting information:

meals made with Okyo

estimated savings per meal

estimated homemade cost versus comparable takeout/restaurant cost

total estimated savings from completed Okyo meals

Only show metrics Okyo can actually calculate or defensibly estimate.

Visual Direction

Savings may use a green accent.

Do NOT turn the whole dashboard green.

The main Okyo environment stays consistent.

MACROS SECTION

Primary Metric

Average protein per Okyo meal

This should summarize recipes/meals that Okyo actually knows about.

Supporting Metrics

Show useful averages such as:

average calories

average protein

average carbohydrates

average fat

Only calculate these from scanned, generated, saved, or completed Okyo recipes where nutrition information exists.

IMPORTANT:

Do NOT imply these values represent the user's entire daily nutrition intake.

Do NOT show concepts such as:

protein remaining today

calories remaining today

daily macro completion

unless Okyo genuinely has enough complete food-intake data to support them.

Visual Direction

Macros may use a blue, lavender, or purple accent.

Do NOT turn the app into a dark fitness dashboard.

Keep it unmistakably Okyo.

HEALTH SECTION

Primary Metric

Goal-friendly meals

Meaning:

Recipes made or edited in Okyo that match the user's selected health or dietary preferences.

Supporting Metrics

Possible supporting information:

healthier recipe edits

meals matching dietary preferences

recipes adjusted around the user's selected health goals

recipes matching dietary restrictions/preferences

Do not invent a vague or unsupported health score.

Do not assign arbitrary ratings such as:

92% healthy

health score 8.7

perfect nutrition

unless there is a real, defensible system behind the number.

Use only information Okyo can actually determine.

Visual Direction

Health may use warm pink, mint, or soft green accents.

Do NOT give Health its own separate app theme.

4. Recent Dishes

Below the metric carousel, show:

Your recent dishes

Food photography should become a major visual part of the lower dashboard.

Use large, attractive dish imagery.

Each recent dish can show only the most useful supporting information, for example:

dish name

cooking time

protein or calories where useful

estimated savings where useful

Do not overload each food item with every possible metric.

The food should remain the focal point.

5. Primary Scan Action

The dashboard should have one obvious primary action for starting another Okyo experience.

Use a prominent Scan / Add / plus action inspired by the placement and accessibility of the Cal AI reference.

The control can open:

Take Photo

Upload Photo

Describe a Dish

Preserve Okyo's existing product semantics.

Okyo works from:

prepared dish photo or dish description→ reconstructed recipe

Do NOT turn the dashboard into a raw-ingredient/fridge meal generator.

6. Navigation

Preserve the normal Okyo navigation architecture.

The Home dashboard should feel integrated with the rest of the app.

Do not invent an entirely separate navigation style only for Home.

Use Liquid Glass selectively where it improves:

bottom navigation

floating primary actions

overlays

selected controls

Do not make every surface glass.

OKYO BRAND ANCHOR

The shared onboarding BEFORE the Savings / Health / Macros branching is currently the strongest existing representation of Okyo's visual identity.

Use that part of the onboarding as the BRAND ANCHOR for the Home dashboard and eventually the rest of the app.

The dashboard should visibly feel like it belongs to the same product.

Preserve qualities such as:

warm cream foundation

strong food imagery

playful but premium personality

bold typography

intentional Kiko usage

clean hierarchy

bright but controlled accent colors

GLOBAL DASHBOARD DESIGN RULES

Use graph3.webp as the structural reference for Home.

Follow Cal AI's dashboard hierarchy closely where it benefits Okyo.

Translate that structure into Okyo's visual identity.

Keep one dashboard for every user.

Personalization changes which metric carousel category appears first.

Savings, Macros, and Health use accent colors only.

Do NOT create different full-screen themes for each goal.

Keep the warm cream Okyo foundation.

Major expressive headlines should use the approved heavy / ultra-condensed sans-serif direction.

Use short copy.

Minimize subtext.

Avoid long explanatory paragraphs.

Do not show internal labels such as:

ILLUSTRATIVE EXAMPLE

PERSONALIZED PLAN

YOUR FUTURE

OKYO DEMO

Most of the usable screen should feel intentionally occupied.

Avoid huge unexplained empty areas.

Do not fill space just for the sake of filling it.

Food should dominate food-related sections.

Kiko should only appear when Kiko improves the composition or emotional experience.

Do not put everything inside white rounded cards.

Avoid nested card-on-card layouts.

Use Liquid Glass selectively.

Keep visual hierarchy obvious.

Avoid excessive explanatory text around metrics.

Every metric displayed must come from data Okyo can actually support.

Never manufacture unsupported savings, nutrition, or health claims.

Preserve existing Okyo functionality while redesigning the presentation.

CORE HOME PRINCIPLE

One Okyo dashboard for everyone.

Savings, Health, and Macros change what information is prioritized first.

They do NOT change what Okyo looks like.
